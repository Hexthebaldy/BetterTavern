## 1 一句话

阅读页每一回合正文的最后一行有“画这一幕”。点了以后，先用导演的模型把这一回合写成一段英文画面描述，
再交给玩家在“设置 › 外部服务”里配好的出图服务（文生图）画一张横图，图插在这一回合的正文下面。

出图服务就是工作台做封面用的那一套（[workbench.md](workbench.md) 第 6 节）：按接口协议接，
`openai_images`、`openai_chat`、`gemini` 三种，玩家填地址、模型名和 Key。官方不提供出图服务。

## 2 和 SillyTavern 对照

| | SillyTavern（Image Generation 扩展） | 我们 |
| --- | --- | --- |
| 画什么 | 好几种：画角色、画角色的脸、画“我”、画整个故事、画最后一条消息、背景 | 一种：画这一回合。玩家可以写一句“想看什么”（例如“沈知微的特写”），画某个人也靠它 |
| 画面描述谁写 | 让聊天的模型按模板写一段提示词 | 一样：导演的模型写一段英文画面描述，同时说出画里有谁 |
| 人物长相前后一致 | 靠提示词里的角色描述 | 提示词里有每个人的描述；另外把画里的人的卡封面（“我”用人设头像）当参考图一起发，服务不收参考图时就不带 |
| 什么时候画 | 玩家用命令或按钮画；也能让模型自己决定什么时候画 | 只在玩家点“画这一幕”时画，不自动画 |
| 图放在哪 | 作为一条新消息插进聊天，模型之后也看得到图的说明 | 放在这一回合的正文下面，不进模型的上下文，不影响故事 |
| 出图服务 | 接十几家 | 按协议接，三种协议能接大多数服务 |

## 3 怎么画

`POST /v1/turns/{turn_id}/images` 检查完就插一行“正在画”（`turn_images`，`pending`）并放一个后台任务 `story.image`，马上返回；
客户端每 3 秒问一次 `GET /v1/turn-images/{image_id}`，直到画好或失败。worker 里（`runtime/illustration_runner.py`）：

1. **读材料**（`services/illustration_store.py`）：
   - 这一回合玩家的行动和正文（多角色的局每段前面带名字），上一回合正文的结尾（让场景接得上）；
   - 世界的标题、设定、基调，世界状态里此刻的地点和它的描述；
   - 画里可能有的人：主角（玩家写的主角设定，没写时用开局设定里的；用人设开局的带上人设头像），
     卡里的角色（开局时卡的描述，封面取这一局记下的或剧本里那张卡现在的），
     世界状态里此刻在场、又不是卡里角色的人（只有描述，没有参考图）；
   - 玩家写的“想看什么”和画风。
2. **写画面描述**（`runtime/agents/illustrator.py`，提示词 `runtime/prompts/<lang>/illustrator.j2`）：
   导演的模型（`task` 是 `illustrator`，`max_tokens` 1024）回一个 JSON：`{"prompt": 英文画面描述, "people": [画里有谁]}`。
   要求它挑这一回合最有画面感的一刻（玩家写了想看什么时按玩家的），写清楚谁在画里、长相衣着、动作表情、地点光线、镜头构图，
   把正文里的“我”换成主角的样子，不写对白和画里的文字，不写画风。
   回的不是 JSON 但有文字时整段当画面描述用（不带参考图）。用官方模型时照样扣点数（一次几点）。
3. **出图**：选了画风时在描述后面拼一句 `Style: …`（动漫、写实、水墨、油画、胶片、平涂换成英文说法）。
   `people` 里有封面或头像的人，按顺序带上当参考图，服务支持几张带几张；
   带了参考图报 `http`、`unsupported`、`bad_response` 时去掉参考图再画一次（多半是服务不支持带图的那个接口）。
   画幅是横版（`landscape`，默认 1536×1024，可以在出图服务的设置里改尺寸）。
4. **存图**：下载（服务给的是地址时）、清洗（`importers/images.py`），缩到长边不超过 1536，存成 WebP（一张两三百 KB）。
   先做带条件的 UPDATE（还在画、没超过时限才改成 `ready`），再写图片、删掉这一回合旧的图。图片算进每个人 200 MB 的图片空间。

日志里不写正文和画面描述，只记图的编号、协议、带了几张参考图、多大、用了多久、失败的原因。

## 4 规则

- **能画哪些回合**：写完了的（`replied`、`committed`），开场、结局也能画；生成中、失败的、被回退掉的不能画（409 `TURN_NOT_SETTLED`）。多角色的局按整回合画，不按每个人那一段画。
- **一次一张**：同一回合同时只画一张（409 `IMAGE_PENDING`）；一个人同时最多画 3 张（429 `TOO_MANY_IMAGES`）。
- **时限**：从点下去算起超过 3 分钟还没画好就当失败（`timeout`）。后台任务开始时先看排队等了多久，剩下的时间才是它能用的；worker 重启、任务卡住都不会让客户端一直转圈。
- **一回合只留一张**：新的一张画好时，旧的那张和没画出来的记录一起删掉（图片没有别处在用时也删掉）。重画失败时旧图还在。
- **画风**：带了画风就记成这一局的（`playthroughs.settings.image_style`），下次不带就用它。
- **不进上下文**：图只给人看，导演、世界状态 agent 都看不到，不影响故事。
- **回退和重试**：被回退掉的回合，它的图跟着一起看不见（和回合一样留着）；重试出来的新回合没有图。
- **删掉**：玩家删一张图就真删，图片空间腾出来。删一局时这一局的图一起删掉。
- **花费**：出图用的是玩家自己的服务，钱花在玩家自己的账上，不扣点数；写画面描述用官方模型时扣点数，画没画成都算。
- **重试**：后台任务不自动重试（`max_attempts` 是 1），重画要再花一次出图的钱，交给玩家点“再试一次”。

## 5 没画出来的原因

`turn_images.error`，客户端按它翻译：

| 原因 | 什么情况 |
| --- | --- |
| `route_missing` | 没有导演模型，没法写画面描述 |
| `model_failed` | 写画面描述时模型出错，或者什么都没写出来 |
| `tool_missing` | 出图服务在点下去以后被删了 |
| `storage_full` | 图片空间满了 |
| `timeout` | 3 分钟没画完 |
| `auth` | 出图服务说 Key 不对 |
| `quota` | 出图服务的额度用完了，或者限流 |
| `blocked` | 出图服务按内容规则拒绝了这张图 |
| `http`、`network`、`bad_response`、`unsupported` | 出图服务报错、连不上、回的东西不对、不支持 |

## 7 确认方案时定下的

2026-10-30 定的：

1. 只在玩家点“画这一幕”时画，不做“每回合自动配图”，也不让导演挑关键场面自动画（自动画容易不知不觉花多）。
2. 官方先不提供出图：只用玩家自己配的出图服务。理由是运营方要另买一家出图服务的 Key，
   有人用运营方的 Key 画出格的图，服务商可能封号；以后要加，像官方搜索那样补上。
3. 其余按方案：一回合只留一张、图不进上下文、回退跟着回合走、删掉就真删、3 分钟超时、横版 3:2、存成 WebP。
