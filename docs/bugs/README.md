这里记录修过的重要 bug：会造成安全问题、数据问题，或者上线后才会暴露的那一类。普通的小毛病看提交记录就够了，不用写在这里。

每份记录写清楚六件事，让没参与修复的人也能看懂：

1. **现象**：用户或运维会看到什么。
2. **原因**：为什么会这样，问题出在哪段代码或哪个配置。
3. **影响范围**：哪些部署、哪些用户会碰到，严重到什么程度。
4. **修复**：改了什么，以及为什么这样改。
5. **验证**：用什么测试证明修好了；没能验证的部分也写出来。
6. **遗留**：这次没处理、以后要注意的地方。
