## 1 一句话

阅读页每一回合有“朗读”，点了就从这一回合的第一段读起，读到哪一段就在那一段左边标一条墨线。也可以打开“自动朗读新回合”。

声音有两种来源：

- **设备自带的声音**：手机和电脑系统里本来就有，不用配置，不花钱；
- **玩家自己配的语音服务**：在“设置 › 外部服务”里加，声音更自然，钱花在玩家自己的账上。官方不提供语音服务。

## 2 和 SillyTavern 对照

| | SillyTavern（TTS 扩展） | 我们 |
| --- | --- | --- |
| 声音从哪来 | 接了十几家，包括系统自带、ElevenLabs、OpenAI、MiniMax 等 | 设备自带的声音，加上按协议接玩家自己的服务 |
| 什么时候读 | 每条消息上有朗读按钮，另有“自动朗读”开关 | 一样：每回合一个“朗读”，再加一个“自动朗读新回合” |
| 读哪些字 | 可以只读引号里的，跳过星号里的 | 旁白和对白都读，对白可以换一个声音 |
| 每个人的声音 | 一张声音表，每个角色、每个人设各选一个声音 | 旁白一个、对白一个；多角色的局里每个角色再各选一个 |
| 语音输入 | 发送键旁边有话筒 | 不做：系统的输入法都有语音输入 |

## 3 语音服务

按接口协议接，不按厂家接（`providers/speech/`）：

| 协议 | 请求 | 能接什么 |
| --- | --- | --- |
| `openai_speech` | `POST {base}/audio/speech`，回声音文件 | OpenAI 的 gpt-4o-mini-tts、硅基流动的 CosyVoice、各种中转和自己架的服务 |
| `gemini` | `POST {base}/models/{model}:generateContent`，回 base64 的 PCM，服务端包成 wav | Gemini 的朗读模型 |
| `elevenlabs` | `POST {base}/text-to-speech/{voice}`，回 mp3；声音列表从 `GET {base}/voices` 读 | ElevenLabs |

豆包、MiniMax、Fish Audio 各有自己的接口格式，先不接。

客户端把一小段文字发给 `POST /v1/speech`，服务端解开 Key、调玩家配的服务，把声音原样传回来。

- Key 不离开服务器，和出图一样；
- 声音不存数据库，不占图片空间。同一小段在这台设备上读过一次就留在本机，再读不重复花钱；
- 语速由客户端放的时候调，换语速不用重新合成；
- 收到的不是声音（有的服务出错时也回 200 加一段 JSON）或者超过 32 MB 都算 `bad_response`；
- 一小段最多 1000 字；每人每分钟最多 60 小段；一小段最多等 60 秒；
- 不扣点数；日志只记服务、字数、多大、用了多久、失败的原因，不写文字。

## 4 没读出来的原因

`SPEECH_FAILED` 的 `reason`，客户端按它翻译：

| 原因 | 什么情况 |
| --- | --- |
| `auth` | 语音服务说 Key 不对 |
| `quota` | 语音服务的额度用完了，或者限流 |
| `blocked` | 语音服务按内容规则拒绝了这段文字 |
| `timeout` | 60 秒没读完 |
| `http`、`network`、`bad_response`、`unsupported` | 语音服务报错、连不上、回的东西不对、不支持 |

## 5 怎么切、怎么读

规则在 `packages/core/src/play/speech.ts`，播放顺序在 `speechPlayer.ts`，网页和 App 共用；怎么出声各自写（`speechEngines.ts`）。

- **读哪些字**：只读正文。“我的行动”、选项、状态提示不读；多角色的局每段前面的名字不读；排版记号（星号、反引号等）去掉；只有标点的（比如“……”）跳过。
- **切成小段**：按段落切，和界面上的段落一一对应；一段太长（语音服务 300 字，设备自带的声音 120 字：Chrome 的在线声音读十几秒会断）在句子结尾切，一句还太长在逗号处切，还太长硬切。
- **对白**：对白和旁白不是同一个声音时，引号里的话（“”「」『』和英文引号）单独切出来，去掉引号。没写完的引号，后面都算对白。
- **用哪个声音**：引号外用旁白的声音（`null` 是这个来源默认的声音）；引号里的话依次用这个人的声音（多角色的局）、对白的声音、旁白的声音。
- **还在写的回合**：最后一段后面出现换行才算写完。切法只看写完的段落，所以新写出来的只会加在后面。
- **播放**：读的时候提前取下一小段，段和段之间不用等。写好的读完了就等着（`waiting`），写出新的一段接着读；回合写完了读完就结束。
- **读不出来**：停在这一小段，写原因，“重试”接着这一小段。
- **设置存在设备上**：设备自带的声音每台设备不一样。声音按来源分开记（设备自带的、每个语音服务各一份），多角色的声音再按局分开。网页在 `bt.prefs` 里，App 是文档目录里一个单独的文件（钥匙串一项放不下）。选的服务被删了时退回设备自带的声音。

设备自带的声音：网页用浏览器的朗读（`speechSynthesis`），App 用系统的朗读（`expo-speech`）。安卓的系统朗读不能暂停，暂停时停掉这一小段，继续时从这一小段的开头重新读。系统朗读的停止是异步的：停了马上读下一小段，iOS 会把下一小段一起取消（2026-11-03 实测），所以要等系统回话说停了（App 最多等 500 毫秒，网页 300 毫秒）再开始。

语音服务的声音：网页取回来放进一个 `<audio>`，存在内存里，关掉页面就没了；App 下载到缓存目录再放（`expo-audio`），最多留 400 个文件。语速在放的时候调。

## 6 界面和规则

网页和 App 一样的部分：

- **朗读**：每一回合一个“朗读”，读这一回合时写“朗读中”，点一下停。
- **读到哪一段**：那一段左边一条墨线，文字不挪动，页面不自动滚动。
- **播放条**：读的时候浮在底部（App 在操作栏上面，平板上在阅读区里居中，最宽 560）：写“第 12 回合 · 第 2 段 / 共 3 段”，有暂停、下一段、停止；等声音超过 0.7 秒才写“正在准备声音…”（小段之间也会短暂地等，字不能一闪一闪）；读不出来时写原因，带“重试”。
- **朗读设置**：声音从哪来、旁白的声音、对白的声音、语速（0.8～1.5 倍）、自动朗读新回合、试听；多角色的局（阅读页打开时）多一块每个角色的声音。入口在“设置”和阅读页的“更多”；“更多”里还有一个自动朗读的开关。
- **外部服务页**：多一格“语音服务”：选协议，填 Key、地址、模型名、默认声音（可以不填）。测试成功时把试听的那句话放出来。

规则：

- **自动朗读**默认关。打开以后边写边读：新回合每写完一段就读那一段。打开故事时已经写好的回合不读，回退以后也不读。正在读旧回合时新回合来了，换到新回合；玩家按了暂停时不换。被玩家停掉的回合不再自动读一遍。
- **回退和离开**：正在读的回合被回退了就停下；失败的回合被关掉就停下；离开阅读页也停下。
- **切到后台**：App 退到后台就停（第一版不做后台播放）；网页切到别的标签页接着读。

不一样的地方：

| | 网页 | App |
| --- | --- | --- |
| “朗读”在哪 | 鼠标移到一回合上，右上角和“画这一幕”一起出现；触屏的浏览器上一直显示在这一回合末尾 | 正文后面靠右一行小字，和“画这一幕”（或者“重画”“删掉”）同一行 |
| 选声音 | 下拉框 | 点一行在下面展开一张单选的列表 |
| 浏览器的限制 | 页面被点过才能出声。没点过时自动朗读读不出来，播放条写原因，点“重试”就好 | 没有这个限制；手机静音键打开时也出声 |

## 7 确认方案时定下的

2026-11-03 定的：

1. 官方不提供朗读服务：设备自带的声音不用配就能听。以后想加，再像官方搜索那样补上。
2. 旁白一个声音、对白一个声音；多角色的局里每个角色再各选一个声音（那一段引号里的话用他的声音）。不做“让模型标这句话是谁说的”：要多花钱，要多等，还会标错。
3. 不做语音输入：手机输入法、Mac、Windows 都自带语音输入。
