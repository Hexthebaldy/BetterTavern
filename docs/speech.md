## 1 一句话

阅读页每一回合有“朗读”，点了就从这一回合的第一段读起，读到哪一段就在那一段左边标一条墨线。也可以打开“自动朗读新回合”。

声音有两种来源：

- **设备自带的声音**：手机和电脑系统里本来就有，不用配置，不花钱；
- **玩家自己配的语音服务**：在“设置 › 外部服务”里加，声音更自然，钱花在玩家自己的账上。官方不提供语音服务。

## 2 和 SillyTavern 对照

| | SillyTavern（TTS 扩展） | 我们 |
| --- | --- | --- |
| 声音从哪来 | 接了十几家，包括系统自带、ElevenLabs、OpenAI、MiniMax 等 | 设备自带的声音，加上按协议接玩家自己的服务 |
| 什么时候读 | 每条消息上有朗读按钮，另有“自动朗读”开关 | 一样：每回合一个“朗读”，再加一个“自动朗读新回合” |
| 读哪些字 | 可以只读引号里的，跳过星号里的 | 旁白和对白都读，对白可以换一个声音 |
| 每个人的声音 | 一张声音表，每个角色、每个人设各选一个声音 | 旁白一个、对白一个；多角色的局里每个角色再各选一个 |
| 语音输入 | 发送键旁边有话筒 | 不做：系统的输入法都有语音输入 |

## 3 语音服务

按接口协议接，不按厂家接（`providers/speech/`）：

| 协议 | 请求 | 能接什么 |
| --- | --- | --- |
| `openai_speech` | `POST {base}/audio/speech`，回声音文件 | OpenAI 的 gpt-4o-mini-tts、硅基流动的 CosyVoice、各种中转和自己架的服务 |
| `gemini` | `POST {base}/models/{model}:generateContent`，回 base64 的 PCM，服务端包成 wav | Gemini 的朗读模型 |
| `elevenlabs` | `POST {base}/text-to-speech/{voice}`，回 mp3；声音列表从 `GET {base}/voices` 读 | ElevenLabs |

豆包、MiniMax、Fish Audio 各有自己的接口格式，先不接。

客户端把一小段文字发给 `POST /v1/speech`，服务端解开 Key、调玩家配的服务，把声音原样传回来。

- Key 不离开服务器，和出图一样；
- 声音不存数据库，不占图片空间。同一小段在这台设备上读过一次就留在本机，再读不重复花钱；
- 语速由客户端放的时候调，换语速不用重新合成；
- 收到的不是声音（有的服务出错时也回 200 加一段 JSON）或者超过 32 MB 都算 `bad_response`；
- 一小段最多 1000 字；每人每分钟最多 60 小段；一小段最多等 60 秒；
- 不扣点数；日志只记服务、字数、多大、用了多久、失败的原因，不写文字。

## 4 没读出来的原因

`SPEECH_FAILED` 的 `reason`，客户端按它翻译：

| 原因 | 什么情况 |
| --- | --- |
| `auth` | 语音服务说 Key 不对 |
| `quota` | 语音服务的额度用完了，或者限流 |
| `blocked` | 语音服务按内容规则拒绝了这段文字 |
| `timeout` | 60 秒没读完 |
| `http`、`network`、`bad_response`、`unsupported` | 语音服务报错、连不上、回的东西不对、不支持 |

## 7 确认方案时定下的

2026-11-03 定的：

1. 官方不提供朗读服务：设备自带的声音不用配就能听。以后想加，再像官方搜索那样补上。
2. 旁白一个声音、对白一个声音；多角色的局里每个角色再各选一个声音（那一段引号里的话用他的声音）。不做“让模型标这句话是谁说的”：要多花钱，要多等，还会标错。
3. 不做语音输入：手机输入法、Mac、Windows 都自带语音输入。
