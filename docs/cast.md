## 1 一句话

剧本里有两张以上的卡时，普通回合不再由导演一个人写所有人：这一回合轮到谁说话，就单独请求一次模型写他，
写的时候只给他看他自己那张卡和他知道的秘密；几个人一个接一个写，后说的人看得到前面的人刚说了什么，
最后再请求一次写给玩家的两个选项。开场和结局照旧由导演写。

这一局有哪些角色，在开局搭世界时记下（`playthrough_cast`）：剧本里的每张卡一个，位置就是卡在剧本里的顺序，
名字是卡的名字，头像是卡的封面。之后改卡、改剧本都不影响这一局。一张卡的剧本、这个功能上线以前开的局没有角色，
照旧由导演一个人写，什么都不变。

## 2 和 SillyTavern 对照

| | SillyTavern 的群聊 | 我们 |
| --- | --- | --- |
| 一回合谁写 | 被挑中的角色每人单独生成一条消息，用自己的卡 | 一样；另外有“旁白”（导演）写环境、路人、主角独自行动的结果 |
| 怎么挑人 | 四种：按提到的名字加“话多程度”抽签 / 按列表一个接一个 / 随机挑这一轮还没说话的 / 只有手动点的人 | 一种固定的规则（第 3 节）：点名 → 行动里提到的 → 在场的人里最久没开口的；不抽签、不随机 |
| 话多程度（talkativeness） | 每张卡一个数，抽签用 | 不做 |
| 暂时不让某人说话 | 可以（muted） | 可以（“先不出场”），整局记着，回退不改 |
| 玩家不说话，让他们接着说 | 空着发送就是让下一个角色接着说 | 一样（行动来源 `continue`） |
| 自动模式（玩家不操作，隔几秒自动接着说） | 有 | 不做 |
| 一回合最多几个人 | 不限 | 不限 |
| 别人的卡看不看得到 | 默认看不到（可以设成把所有卡拼在一起） | 看不到；别人只能从故事里认识 |
| 选项 | 没有 | 照样给两个，几个人写完以后单独请求一次 |
| 单独重写某一个人的那一段（左右滑动换一条） | 有 | 不做：失败或重试都是整回合 |

## 3 谁说话

从上往下看，哪一条先满足就按哪一条（`domain/story/cast.py` 的 `choose_speakers`）：

1. 玩家点了名（行动的 `speakers`）：按点的顺序，旁白也可以点；
2. 玩家的行动里写了谁的名字：按名字出现的先后。除了卡的名字，世界状态里那个人物的名字和别名也算（比如“掌柜”）；
   只有一个字的名字不算，免得误中；
3. 都没有：在场的角色里最久没开口的一个（从没说过话的最先，一样久的按卡的顺序）。
   - “在场”取自世界状态里的场景。世界状态是后台整理的，可能比故事晚一回合；
   - 场上一个角色都没有时，由旁白写；
   - 闪电模式没有世界状态，就在所有角色里挑；角色的名字和世界状态里的人物一个都对不上时也这样；
   - 玩家这一回合不行动（`continue`）时，不挑上一回合最后说话的那个，只剩他一个时除外。

“先不出场”的角色不会被挑中，点了他的名也不算；全都先不出场时由旁白写。一回合说话的人数不设上限，点了几个就是几个。
规则是确定的：同样的情况结果一样，方便测试和重放。

## 4 一回合怎么走

（`runtime/cast_turn.py`，由 `runtime/runner.py` 在多角色的局的普通回合里调用。）

1. 按第 3 节定下这一回合谁说话、按什么顺序；
2. 一个接一个写。每个人开写前推一条 `speaker.started`（`{"index", "speaker", "name"}`），之后的 `narrative.delta` 都是他这一段的。
   每个人的请求和导演的一样：同一个模型、同样的执行循环，有不在上下文里的旧回合时也能用召回工具，也能写隐藏备注；
3. 模型照着历史在开头写了一行名字（“【阿苓】”）时去掉它：先攒着第一行，看出是名字就不推给玩家，存下来的也没有；
4. 都写完以后照几段拼起来的全文补两个选项（和导演没给选项时一样，用补选项的小请求；补不齐时玩家自己写）；
5. 存回合：每一段是谁写的存在 `turns.segments`，叙述 `narrative` 是这几段拼起来、每段前面一行名字的全文，
   隐藏备注拼在一起、每条前面带名字。后台整理世界状态、章节摘要、召回都直接读这段全文，不用改。

中间任何一个人写失败，这一回合按失败算：已经写好的几段加上没写完的半段存成草稿（`narrative` 和 `segments` 都有），
已经花掉的几次请求都记进 `agent_runs`。重试时所有人重写。

花费：几个人说话就是几次完整的请求，再加一次很短的选项请求。几次请求只有最后一条消息不同，前面整段（规则、设定、原文）
命中服务商的前缀缓存。等待：第一个人开始出字和以前一样快，整回合写完的时间是几个人加起来。

## 5 每个人写的时候看到什么

装配在 `runtime/context/assembler.py`（多角色的局那几样在同级的 `cast.py`）。

- **system**：和导演的一样排（规则、故事设定、主要人物、常驻世界书、回顾），只是规则换成“每次写一段、最后一条消息说写谁”，
  加上角色的名单，并且**不放任何一张卡的原文、指令和示例**（闪电模式也不放）。所以几个人、几回合的 system 一字不差。
- **原文回合**：和导演的一样。多角色的回合在历史里是带名字的全文；玩家让他们接着说的回合，用户那一条写“这一回合我没有行动”。
- **最后一条消息**（`cast.turn`）：
  - 状态块：写角色时只给他看他知道的——公开的事实加上他知道的秘密（`facts.known_by` 里有他），没有“仅导演可见”一节，
    线索不带答案；角色和世界状态里的人物按名字对上，对不上的只看公开的事实。旁白看得到全部，和导演一样；
  - 大纲、这一回合挑中的世界书、召回提示，和导演的一样；
  - 玩家的行动，或者“这一回合我没有行动”；
  - 这一回合前面已经写好的几段（带名字）；
  - 这一次写谁，以及他的卡：写角色时只有他自己的卡——描述、性格、场景、卡作者的系统提示、对话示例、后置指令和角色备注；
    写旁白时是每张卡卡作者的系统提示和后置指令、角色备注（闪电模式没有世界状态，再加上每张卡的描述、性格、场景），不给对话示例。
- **开场和结局**：照旧由导演写，最后一条消息里放每张卡的系统提示、对话示例、后置指令和角色备注（闪电模式再加上原文）。

卡的内容在最后一条消息里，每次都要重新算（不命中缓存），换来的是前面整段对所有人、所有回合都一样。

## 6 界面

网页（`pages/play/CastPicker.tsx`）和 App（`features/play/CastParts.tsx`）一样，只在多角色的局（两个以上角色）里出现：

- 每一段：角色写的那一段左边是头像（开局时那张卡的封面，没有封面按名字画），上面一行名字；旁白那一段和普通叙述一样，没有头像。
  生成中按 `speaker.started` 一段一段拼，断线重放时按段号对齐不重复；状态写“某某正在说…”（先查旧回合时照旧是“正在回想前情…”）。
- 选项上方“在场的人”一排：每个角色一块（头像、名字），最后是“旁白”。点一块是点名，再点取消，可以点好几个，按点的顺序说；
  每块右边的小眼睛是“先不出场 / 回来”，先不出场的变淡、虚线框，点不了名。点了名时下面一行写“点名：阿苓、旁白”和“清除”。
  交了行动（选项、自己写、让他们接着说）就清掉点名。
- “让他们接着说”：网页在“自己写”下面，App 在选项下面；这一回合不行动。故事流里“我的行动”那一行写“（让他们接着说）”。
- 左栏回想（网页）取第一段的正文，不取名字那一行。
- 旧版 App 不认识这些：看到的是每段前面带“【阿苓】”的一整段文字，生成中各段连在一起，写完以后换成带名字的全文。

## 7 确认方案时定下的

- 选了 B：每个角色单独请求一次，而不是导演一个人写、只加点名之类的控制（A）。
- 不加开关：所有两张卡以上的剧本都这样写；以前开的局照旧由导演写。
- 有旁白：开场、结局、场上没有角色时由导演写，玩家也能点名旁白。
- 照样给两个选项，每回合多一次很短的请求。
- 一回合说话的人数不设上限。
- 不做：话多话少、自动往下写、随机挑人、按列表轮流、单独重写某一个人的那一段。
