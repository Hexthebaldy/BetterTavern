## 做法

1. **提交**：一条一个提交，标题带编号，例如 `fix(client): A1 失败后自己写的行动放回输入框`。在同一个提交里，把下面总表里这一条的“状态”改成“完成”。
2. **逻辑放哪**：两端都要的逻辑放进 `packages/core`，写成纯函数或 reducer 的分支，用 `node --test` 测。返回文字的函数，中文、英文各测一遍。页面只负责接线。
3. **文案**：中文是源语言。新增或改动的 key，`zh`、`en`、`ja` 三份一起改。本文给了三种语言的，照抄；只给了中文的，按 docs/i18n.md“写法约定”翻译：英文句首大写；日文的说明用です・ます体，按钮用名词或动词原形，引号用「」。
4. **检查**：每条做完都跑 `npm test`、`npm run typecheck`、`node scripts/check-i18n.mjs`。每一批做完时跑一次 `make web-e2e`，跑不起来就在汇报里说明。
5. **文档**：
   - 改了行为的，在同一个提交里更新 docs/client.md 对应的段落。
   - 改了设计规则的（快捷键、色板、浮条时长），同时改 `docs/design/ui/` 下对应的说明。
   - 每条里写了具体要改哪一行文档。
6. **不要动的**：下面这些是之前刻意定下的做法。
   - 网页的 Key 输入框不用 password 类型；
   - 网页没有“粘贴”按钮；
   - 网页的浮条停 4 秒，鼠标停在上面时不消失；
   - 网页没有服务器切换。
7. **范围**：不改服务端接口，也不改表结构。
8. **对不上时**：现象在代码里已经不存在，或者改法和代码现状冲突，先停下来说明，不要硬套。

# 第一批

## A1 行动写了一半不会丢

**现象**

- 发送时先清空草稿，再提交：
  - 手机：`apps/mobile/app/play/[id]/index.tsx:259-263`；
  - 网页：`apps/web/src/pages/play/PlayPage.tsx:217-221`，连浏览器里存的草稿一起删。
  - 之后这段文字只在 state 里：`pending.action.text`，请求还没结束时 `submission.action.text` 里也有。
- 生成失败后点“换个行动”会调用 `dismissError`，`packages/core/src/play/turnMachine.ts:220-223` 把 pending 清空，文字跟着没了。按钮位置：手机 `apps/mobile/src/features/play/TurnActions.tsx:82`，网页 `apps/web/src/pages/play/TurnActions.tsx:100`。
  - 最常见的是内容被服务商拦截（CONTENT_BLOCKED）：玩家只想改几个字，却要整段重打。
- 故事在别处被推进时（stale，`packages/core/src/play/playSession.ts:245、250`），`turnMachine.ts:201-202` 同样把这段文字丢掉，而且没有任何提示。
- 失败时，底栏的“自己写…”是灰的，因为 `canAct` 只认 idle（`turnMachine.ts:286-288`）。对应位置：手机 `features/play/BottomBar.tsx:101、135`，网页 `pages/play/BottomBar.tsx:158、195`。
- 手机的草稿只是页面 state（`index.tsx:122`），回到存档列表、App 被系统收掉都会丢。网页按故事存在浏览器里（`PlayPage.tsx:140-148`，键名见 `pages/play/reading.ts:34` 的 `draftKey`）。

**改法**

1. **core**（turnMachine）：`dismiss_error` 和 `stale` 丢掉的如果是自己写的行动，把文字记在 state 上。
   - 判断条件：`source === "text"`。失败时看 `pending.action`，stale 时看 `submission.action`。
   - 字段例如 `returned: { text: string; why: "dismissed" | "stale" } | null`。
   - `submit` 和新事件 `returned_taken` 把它清掉；PlaySession 加 `takeReturned()`。页面只能通过 `PlayControls` 用到 session，所以两端的 `usePlaySession`（`apps/mobile/src/features/play/usePlaySession.ts`、`apps/web/src/pages/play/usePlaySession.ts`）都要把它暴露出来。
   - 补测试：两种转移都留下文字；选项、开场、写结局不留；取走后为 null。
2. **两端阅读页**：
   - `state.returned` 不为空时取走，放回草稿并展开输入框（`setDraft`、`setWriting(true)`）。
   - 草稿里已经有字时不覆盖：退回的文字放在前面，空一行。
   - `why === "stale"` 时再弹浮条 `play.actionReturned`。
3. **失败时“自己写…”能点**：失败状态下（不是开场失败），底栏的“自己写…”可以点，效果和“换个行动”一样。
4. **手机草稿按故事保存**：
   - 用 expo-file-system，写法照 `apps/mobile/src/observability/persist.ts` 的 `File`、`Paths`；存一个 `drafts.json`，内容是 `{ [playthroughId]: text }`。
   - 写入时机：输入停 500ms 再写。进页面先读回；发出后、清空后删掉这一条。
   - 不要放 SecureStore：单个值有大小上限，2000 个汉字放不下。
   - 同步改 docs/client.md 第 4 节“草稿每个故事一份……”那一句（:336），写上手机也保存。

**文案**

| key | 中文 | English | 日本語 |
| --- | --- | --- | --- |
| `play.actionReturned` | 故事在别处有了新进展，你写的内容放回输入框了 | The story moved on elsewhere, so your text is back in the input box. | 物語が別の端末で進んだため、書いた内容を入力欄に戻しました |

**验收**

- [ ] 自己写一段并发送，让这一轮失败（断网，或者让假模型返回 CONTENT_BLOCKED）。点“换个行动”：输入框展开，里面是刚才那段文字。
- [ ] 失败时点底栏的“自己写…”，结果相同。
- [ ] 选项发出后失败，再点“换个行动”：输入框不展开，草稿不变。
- [ ] 两台设备打开同一个存档。A 先推进一段，B 再发一段自己写的行动：B 同步完后，文字回到输入框，并弹出浮条。
- [ ] 手机：
  - 写一半退回存档列表再进来，草稿还在；
  - 把 App 从后台划掉再打开，草稿还在；
  - 发出后草稿清空。
- [ ] turnMachine 的新测试通过。

## A2 “写结局”不会被回车键提交

**现象**

- 写结局用的是通用的输入对话框，传了 `optional: true`：手机 `apps/mobile/app/play/[id]/index.tsx:203-217`，网页 `apps/web/src/pages/play/PlayPage.tsx:230-244`。
- 手机的输入框是单行，`returnKeyType="done"`，`onSubmitEditing` 直接提交（`apps/mobile/src/components/overlay.tsx:269-270`）。
  - 对话框一打开就弹出键盘。很多人点键盘上的“完成”只是想把键盘收起来，结果结局直接写了，空着也会提交。
  - 对话框正文明明写着“写完后故事就结束了，不能撤销”（`packages/core/src/i18n/zh/play.ts:12`）。
- 网页是 `<form>` 里一个 `<input>`（`apps/web/src/overlay/OverlayProvider.tsx:227-268`），回车就提交。
- “结局方向”最多 2000 字，放在单行框里也很难写。

**改法**

1. 两端的 `PromptOptions` 加 `multiline?: boolean`：手机 `overlay.tsx:48`，网页 `OverlayProvider.tsx:42`。
2. 手机：multiline 时 `TextInput` 设 `multiline`、`submitBehavior="newline"`、`textAlignVertical="top"`，去掉 `returnKeyType` 和 `onSubmitEditing`。高度 3 到 6 行，超出后在框里滚动。`styles.promptInput` 固定了 `height: 52`（`overlay.tsx:512`），多行时换成最小高度和最大高度。
3. 网页：multiline 时换成 `<textarea rows={4}>`。
   - 样式沿用 `.promptInput`，但它固定了 `height: 52px`，上下没有内边距（`apps/web/src/overlay/overlay.module.css:78-88`）。多行时改成 `height: auto`，加上下内边距和最大高度。
   - 回车换行，Ctrl / ⌘ + Enter 等于点确认。
   - 打开时光标放在末尾，不全选。
4. 写结局的两处都传 `multiline: true`。重命名等其他用法不变。
5. docs/client.md 第 3 节写结局那一段（:173-175）补一句：输入框是多行的，回车不提交。

**验收**

- [ ] 手机：打开“写结局”，键盘上的回车键是换行。按回车、收起键盘都不会提交；只有点“写结局”才提交。
- [ ] 网页：在“结局方向”里按回车是换行，Ctrl / ⌘ + Enter 提交。重命名对话框按回车仍然直接保存。
- [ ] 不填方向时点“写结局”照样能写。

## A3 网页：直接打字不会误发选项

**现象**

- 单键快捷键默认打开（`apps/web/src/state/prefs.ts:37`）。焦点不在输入框时，按 A–D 会立刻发出对应的选项（`apps/web/src/pages/play/PlayPage.tsx:286-291`），按 W 开关世界面板（:295-297）。
- 焦点经常不在输入框里：
  - 发送后输入框被卸载（`pages/play/BottomBar.tsx:214-221`），焦点没有放回去，落到页面上；
  - 点了选项后，选项按钮也被卸载。
- 这时玩家习惯性地接着打下一句拼音：
  - 打出 w，世界面板弹出来；
  - 以 a–d 开头的拼音（da、bu、chu、dui……）会直接替他选了一个选项。这一步不能撤销，还白白花了一次生成。
- 这组快捷键是设计稿定的（`docs/design/ui/web/README.md:239`），是设计上的疏忽。

**改法**

1. **A–D 改成“选中”**：
   - 选中的选项用 `.optionOn` 的颜色（浅蓝底、2px 蓝色内描边、字母圆变蓝），但不要缩小：`.optionOn` 里的 `transform: scale(...)`（`apps/web/src/pages/play/play.module.css:296-301`）只属于按下的那一下，选中样式单独写一个类。
   - 选中后滚动到可见（`block: "nearest"`）。
   - 不要把焦点移到按钮上，否则接着按的空格会把它发出去。
   - 再按另一个字母，选中换成那一个。
   - 判断逻辑写成纯函数（放在 `apps/web/src/theme/layout.ts` 或 `pages/play/reading.ts`），补测试。
2. **发出和取消**：
   - 有选中的选项时，按 Enter 才发出。
   - Esc、点页面别处、阶段离开 idle、选项变了，都会取消选中。
   - 用鼠标点选项，仍然直接发出。
3. **提示**：
   - 选中的选项右端显示键帽提示 `play.optionArmed`。
   - 在底栏放一个视觉上隐藏的 `aria-live="polite"` 区域（B24 会复用），选中时写入 `play.optionArmedLabel`。
4. **焦点**：
   - Esc 收起输入框后，焦点回到“自己写…”按钮。
   - 发送后、选完选项后，焦点放到底栏的 toolbar 上（给它加 `tabIndex={-1}`），不要落到“停止”上。
5. **说明文字**：
   - 快捷键表这一行改成 `shortcuts.items.pick`（`packages/core/src/i18n/zh/shell.ts:33`）。
   - 设计稿同步改：`docs/design/ui/web/README.md:239` 快捷键表那一行，:396 的“按 A 选选项”改成“按 A、再按 Enter”，`docs/design/ui/web/layout.ts:189` 的 label。
   - docs/client.md 第 4 节“A–D 选选项”（:332）。

**文案**

| key | 中文 | English | 日本語 |
| --- | --- | --- | --- |
| `shortcuts.items.pick`（改） | 选中一个选项，按 Enter 发出 | Select an option, then press Enter to send | 選択肢を選び、Enter で送信 |
| `play.optionArmed` | `<kbd>Enter</kbd> 发出` | `<kbd>Enter</kbd> to send` | `<kbd>Enter</kbd> で送信` |
| `play.optionArmedLabel` | 已选中 {{key}}，按 Enter 发出 | {{key}} selected. Press Enter to send. | {{key}} を選択しました。Enter で送信します |

**验收**

- [ ] 焦点不在输入框时按 B：B 高亮并滚到可见，没有发出。再按 Enter：B 发出，页面回到最新。
- [ ] 按 B 再按 C，高亮换到 C；按 Esc 或点正文，高亮消失。
- [ ] 发送一段，等它写完，不点输入框直接打“wo da”：世界面板开关一次，A 被高亮，但什么都没有发出。
- [ ] 用鼠标点选项，仍然一次就发出。
- [ ] 发送后按 Tab：焦点从底栏开始，不是从侧栏开头。
- [ ] 快捷键对话框里这一行的说明已经更新。

## A4 断网、超时不再只说“生成失败”

**现象**

- 客户端自己产生的错误码：
  - 连不上服务器、超时：`NETWORK`、`TIMEOUT`（`packages/core/src/api/client.ts:79-89`）；
  - 代理返回网页：`HTTP_502` 这类；
  - 返回内容看不懂：`BAD_RESPONSE`。
- `toTurnError`（`packages/core/src/play/playSession.ts:54-59`）只留下 code、英文的 message 和 retryable，HTTP 状态码丢了。`describeTurnError`（`client.ts:346-353`）只查 `errors.reason`、`errors.turn`、`errors.api`，这几个码都查不到，中文、日文界面就落到“生成失败”。
- 结果有两种：
  - 发送时断网，自动重试大约 15 秒后，失败卡写“生成失败”。其实行动根本没发出去，玩家会以为是模型出了问题，跑去换模型。
  - 离线打开存档时，标题是“故事没能打开”，正文却是“生成失败”。位置：手机 `apps/mobile/app/play/[id]/index.tsx:247-256`，网页 `apps/web/src/pages/play/PlayPage.tsx:318-329`。
- 对应的文案其实都有：`errors.network`、`errors.timeout`、`errors.badResponse`（`packages/core/src/i18n/zh/common.ts:64-66`），只是回合错误没有用上。

**改法**

1. `describeTurnError` 在兜底之前，对客户端自己的错误码沿用 `apiErrorText`（`client.ts:324-343`）的规则：

   | 错误码 | 用的 key |
   | --- | --- |
   | `NETWORK` | `errors.network` |
   | `TIMEOUT` | `errors.timeout` |
   | `BAD_RESPONSE` | `errors.badResponse` |
   | `HTTP_<n>` | `errors.status.<n>`，没有就用 `errors.httpStatus` |

   - 两个函数共用一个小的映射函数。回合错误里没有 HTTP 状态码，`HTTP_<n>` 的 n 从错误码里解析出来（`apiErrorText` 用的是 `error.status`，`client.ts:339`）。
   - 三种界面语言都走这些 key，英文界面也不再显示 “Can't reach the server” 这类原始说明。
   - 补测试。
2. 失败卡：手机 `apps/mobile/src/features/play/TurnActions.tsx:61-92`，网页 `apps/web/src/pages/play/TurnActions.tsx:81-108`。
   - `unsentSubmission(state)`（`turnMachine.ts:306-308`）不为空，说明请求从没被服务端接收。这时正文用 `play.notSent`，重试按钮改叫 `play.resend`。

**现象**

   - 服务重启等原因造成的 CANCELLED（玩家没点停止，或者页面重新加载过）仍用现在的失败卡。

## A7 存档列表自己刷新“正在写开场”

### B11 登录失效时说明原因；网页连不上服务器时不当成没登录

**现象**

- **登录失效时什么都不说**：
  - 刷新令牌被拒（401 或 403）时，`packages/core/src/auth/session.ts:176-178` 直接 `signOut()`。
  - 手机的 `Stack.Protected`（`apps/mobile/app/_layout.tsx:94-105`）把当前页面整个换掉；网页的 `RequireAuth` 跳到 /login（`apps/web/src/app/guards.tsx:18`）。
  - 两边的登录页都没有任何说明。“登录已失效，请重新登录”（`errors.sessionExpired`，`zh/common.ts:68`）写好了，但全项目没有用到。
- **网页连不上服务器会被当成没登录**：
  - 网页打开时要恢复登录。`cookieSession.load`（`apps/web/src/state/AppProvider.tsx:45-60`）只把 401、403 当成没登录，其他错误会抛出。
  - 但 `restore()` 把所有异常都当成“没有会话”（`session.ts:102-108`）。
  - 结果是服务器重启或断网时打开网页，先看到 Logo 闪屏（最长 30 秒），然后被送到登录页，其实 Cookie 还有效。

**改法**

1. **记下退出原因**：SessionManager 记下最近一次退出的原因：`"user"`（主动退出）或 `"expired"`（刷新被拒），通过 AppProvider 暴露出来（例如 `signedOutReason`）。登录成功后清掉。
2. **登录页说明**：原因是 `expired` 时，两端的登录页顶部显示一条 info 色、可以关掉的 Notice，文字是 `errors.sessionExpired`。
3. **网页连不上时停在闪屏**：网页恢复登录时遇到网络错误或 5xx，不进入 signedOut。
   - 停在闪屏上，显示 `describeError(e)` 和“重试”（`common.retry`），点了重新 restore。
   - “重试”要真的再请求一次：网页的 AppProvider 把 restore 缓存成了同一个 Promise（`apps/web/src/state/AppProvider.tsx:96-97`），`SessionManager.restore()` 也只在 restoring 状态下才写入结果（`packages/core/src/auth/session.ts:110`）。这两处都要改。
   - 实现上可以给 `SessionStatus` 加一个状态（例如 `"offline"`），也可以让 restore 把错误交给调用方，选改动小的一种。
   - 手机从本机读令牌，不受影响。
4. **测试**：补 session 的测试，覆盖 expired、user 两种原因，以及恢复时遇到网络错误。

**验收**

- [ ] 让刷新令牌失效（例如在服务端吊销），在手机上随便操作一下：回到登录页，顶部写着“登录已失效，请重新登录”。
- [ ] 主动“退出登录”时，没有这条提示。
- [ ] 网页：停掉服务端再刷新页面，闪屏上显示“连不上服务器……”和“重试”。启动服务端后点“重试”，直接进入，不用重新登录。

  - 设置页的 Page（给 Page 转发 ref）。

### B23 Android：面板里弹出确认框时，返回键先关确认框

> 把握：中。这条是从代码推断出来的，要在 Android 真机或模拟器上确认。

**现象**

- 面板开着时，确认框画在面板自己的 Modal 里（`apps/mobile/src/components/sheet.tsx:77-88` 的 OverlayOutlet）。
- 确认框没有自己的 Modal，所以 Android 的返回键交给了面板的 `onRequestClose={onClose}`（:375），面板被收起。
- 面板一撤销登记，确认框又改到根上弹出（`apps/mobile/src/components/overlay.tsx:220`）。
- 实际场景：在世界面板里点“揭示秘密”（`apps/mobile/src/features/play/WorldSheet.tsx:62-70`），再按返回键：面板没了，“揭示 N 条秘密？”还在，要再按一次。

**改法**

- OutletContext 加 `dialogOpen` 和 `cancelDialog()`。
- Sheet 的 onRequestClose 先判断：自己是最上层，并且有确认框开着。是的话只调用 `cancelDialog()`，否则才调用 `onClose()`。

**验收**

- [ ] Android 上打开世界面板，点“揭示”，按返回键：只关掉确认框，面板还在。再按一次，才关掉面板。

### B24 读屏能听到浮条、确认框的说明和各种状态

**现象**

- **手机，iOS 上听不到**：
  - 浮条和 Notice 只设了 `accessibilityRole="alert"` 和 `accessibilityLiveRegion="polite"`（`apps/mobile/src/components/overlay.tsx:478-480`，`apps/mobile/src/components/feedback.tsx:55-57`）。
  - liveRegion 只在 Android 上起作用，iOS 的 VoiceOver 不会播报，所以“邮箱或密码不正确”“已删除”“删除失败”都没有声音。
  - 阅读页生成失败时也一样：只有写完一段时才会朗读（`apps/mobile/app/play/[id]/index.tsx:167-181`）。
- **网页**：
  - 浮条是 `{toast ? <Toast/> : null}`（`apps/web/src/overlay/OverlayProvider.tsx:132-134`）。`role="status"` 的元素和文字一起插进页面（:281），很多读屏不会播。
  - 阅读页状态区的 `aria-live`（`apps/web/src/pages/play/BottomBar.tsx:47`）只在生成中挂着，写完一段时什么都不读。
  - 确认框只有 `aria-label`（`apps/web/src/overlay/Dialog.tsx:64`），后果说明（例如“删除后这个存档的故事和世界状态都无法恢复。”）没有关联上。删除类确认的默认焦点又在“取消”，所以读屏只读出标题和“取消”。
- **显式的读屏名称盖掉了状态**：
  - 平板的存档卡 `accessibilityLabel={story.title}`（`apps/mobile/src/features/stories/StoryCards.tsx:77`），读不出“正在写开场”“已完结”；
  - 世界书条目（两端 `BookEditor.tsx:77`）读不出“有问题”“常驻”“未启用”；
  - 导演卡片和模型行读不出“Key 无效”“未测试”：手机 `apps/mobile/app/(tabs)/settings.tsx:81`、`ModelsBody.tsx:39-41`，网页 `apps/web/src/pages/settings/SettingsList.tsx:38`、`ModelsBody.tsx:31`。

**改法**

1. 手机：在下面三处调用 `AccessibilityInfo.announceForAccessibility(...)`：
   - `toast()` 里；
   - Notice 挂载时（tone 不是 info、message 是字符串）；
   - 阅读页进入 failed 时。
2. 网页：
   - OverlayProvider 里常驻一个视觉上隐藏的 `role="status"` 区域，toast 时往里写文字。
   - 阅读页底栏的视觉隐藏 `aria-live` 区域（A3 加的）：生成中写状态，写完写 `play.partDone`。
3. 网页 Dialog 加 `describedBy` 参数，DialogCard 的说明加 id，连到 `aria-describedby` 上。
4. 把状态拼进读屏名称：
   - 存档卡：标题加上 `storyStatus(story)?.label`，中间用 `common.comma` 连接；
   - 世界书条目：名称加上状态；
   - `settings.directorLabel`、`models.rowLabel`、`models.rowLabelDirector`：加 `{{status}}`，传入模型状态的文字。

**文案**

| key | 中文 | English | 日本語 |
| --- | --- | --- | --- |
| `play.partDone` | 新的一段写好了 | The next part is ready | 次の場面ができました |
| `settings.directorLabel`（改） | 导演模型 {{model}}，{{status}} | Director model {{model}}, {{status}} | 監督モデル {{model}}、{{status}} |
| `models.rowLabel`（改） | {{name}}，{{status}} | {{name}}, {{status}} | {{name}}、{{status}} |
| `models.rowLabelDirector`（改） | {{name}}，导演，{{status}} | {{name}}, director, {{status}} | {{name}}、監督、{{status}} |

**验收**

- [ ] iOS 打开 VoiceOver：登录失败、删除成功、生成失败都会读出来。
- [ ] 网页用 VoiceOver 或 NVDA：
  - 浮条和“写完一段”会读出来；
  - 删除确认会读出后果说明；
  - 模型行会读出状态。
