# 多语言（i18n）技术方案

> 文档索引：[总览](README.md) · [后端](backend.md) · [客户端](client.md) · [测试](testing.md) · [数据模型](data-model/README.md) · [接口](api/README.md)

手机端和网页端的界面支持中文、英文和日文，服务端给 agent 的提示词也有中文、英文、日文三套。本页写清楚哪些东西随语言变、语言存在哪里、怎么传给服务端，以及写代码时要守住的约定。

## 1 范围

三种语言：中文（源语言，所有文字先用中文写）、英文和日文。以后加一种语言，就是加一份客户端资源和一套服务端提示词（文字和中文差别大的语言再加一份正文字体），不改代码结构（第 6 节）。

随语言变的：

- 手机端、网页端所有界面文字：标题、按钮、提示、空状态、对话框、读屏标签（`accessibilityLabel`、`aria-label`）、输入框占位文字、标签页标题。
- 客户端显示给用户的错误：服务端只给错误码和英文说明，客户端按错误码翻译（第 3 节“错误信息”）。
- 开始新故事表单里的名字建议、内置文风和“不想看到的内容”：英文界面给英文的选项，选中的文字原样发给服务端。
- 服务端给 agent 的提示词，以及拼进模型上下文的固定文字（篇幅说明、世界状态块的标签、开局设定的字段说明）。

不随语言变的：

- 服务端返回的说明（错误的 `title`、回合失败的 `message`、模型测试结果里的 `detail`）：一律英文，不做多语言。
- 故事正文的语言：不做规定，提示词里不写“用某种语言写”。正文一般跟着提示词、角色卡和玩家输入的语言走。
- 角色卡、世界书等用户导入的内容；模型名、服务商的品牌名、token 数（如 `128K`）、错误单号。
- 诊断日志的导出内容（给开发者看，和服务端日志一样用英文）。
- 故事正文的宋体不跟界面语言，跟这一局的语言：日文的局用日文字体，其他用中文字体（自带拉丁字母，英文正文也用它），见第 3 节“字体”。

## 2 几个决定

| 问题 | 决定 | 原因 |
| --- | --- | --- |
| 用什么库 | i18next + react-i18next | 复数、插值、缺 key 时退回源语言、切换语言时组件自动刷新都是现成的；两端都是 React，共用一套资源 |
| 资源放哪里 | `packages/core/src/i18n/`，两端共用 | 两端的文字大部分相同；共用资源保证同一个按钮在两端叫法一样 |
| 界面语言存在哪里 | 设备上的界面偏好（`PrefsProvider`，和外观、阅读设置放在一起），不放服务端 | 语言是这台设备的显示偏好，和外观一样；不同设备可以不同。数据库里的 `users.locale` 保留不用 |
| 设置入口 | 设置首页“其他”组里单独一行“语言”，和外观、连接测试同级 | — |
| 提示词的语言怎么定 | 开局时客户端把当前界面语言传给 `POST /v1/playthroughs`（`language` 字段），存在这一局的 `playthroughs.language` 上；这一局以后的 agent 调用都按它选提示词 | 一局的提示词语言固定：前缀缓存、重放测试依赖同一局的提示词稳定；之后切换界面语言不影响已有存档 |
| 服务端错误 | 全部改成英文，不做多语言；回合失败另带 `reason`（服务商错误的类别），供客户端翻译 | 服务端不需要知道界面语言；客户端按错误码显示两种语言的文字 |

## 3 客户端

### 库与资源

- 依赖：`i18next`、`react-i18next`（两端），手机端另加 `expo-localization`（读系统语言，Expo Go 自带）。版本锁定，不跟最新补丁。
- `packages/core/src/i18n/`：
  - `zh/`：源语言，按领域分文件（`common`、`shell`、`auth`、`stories`、`play`、`library`、`settings`），`zh/index.ts` 合在一起，定义所有 key。
  - `en/`：同样的文件，类型由中文推出（`types.ts` 的 `Messages`），少 key 或多 key 时类型检查不通过。
  - `ja/`：同样的文件，类型同样由中文推出；日文没有单复数，用 `MessagesOtherOnly`，和中文一样只写 `key_other`。
  - `index.ts`：创建两端共用的 i18next 实例并同步初始化（资源打在包里，不按需下载），导出 `i18n`、`applyLanguage()`、`resolveLanguage()`、`currentLanguage()`、`lookup()`（按运行时拼出来的 key 取，查不到返回 null），以及语言表：`LANGUAGES`、`LANGUAGE_NAMES`（每种语言用自己的文字写的名字）、`LANGUAGE_TAGS`（网页 `lang` 属性的写法：`zh-CN`、`en`、`ja`）。
  - `plural.ts`：运行环境没有 `Intl.PluralRules` 时补一个最小实现：中文、日文没有单复数，其他按英文的规则（i18next 没有它会把中文、日文的单数也当成 `one`）。
  - `i18n.test.ts`：每种语言的 key 都和中文一一对应、插值变量和组件标签（`<mono>`、`<link>`、`<kbd>`）一致、英文的复数齐全（日文只有 `_other`）、没有空文字。
- key 分两层：`领域.名字`，例如 `common.retry`、`settings.language`、`play.writingNext`。一级领域大致按页面分：`common`、`time`、`errors`、`nav`、`server`、`auth`、`stories`、`library`、`scenario`、`start`、`cardEdit`、`play`、`reading`、`world`、`settings`、`appearance`、`language`、`account`、`models`、`probe`、`diagnostics`、`shortcuts`、`import`、`notFound`。
- 插值写 `{{name}}`。复数：调用时传 `count`；中文、日文只写 `key_other`，英文写 `key_one` 和 `key_other`。
- 类型：`CustomTypeOptions` 指向中文资源，`t("不存在的key")` 在类型检查时报错。缺 key 时退回中文（`fallbackLng: "zh"`）。

### 写法约定

- 组件里用 `const { t } = useTranslation()`。每个直接渲染文字的组件自己调用，列表里的一行也一样：切换语言时，调用了它的组件会自己重新渲染。`memo` 的组件即使只调用 core 里的函数取文字，也要调一次 `useTranslation()` 订阅语言变化。
- 不在模块顶层算出翻译后的常量（模块加载时语言还没定下来，切换后也不会变）。选项表这类常量里存 id，渲染时再取文字（主题名 `appearance.<id>`、快捷键 `shortcuts.items.<id>`、导航 `nav.<name>`）。
- `packages/core` 里返回文字的函数（相对时间、存档状态、模型状态、开始表单的选项、角色卡检查、错误说明等）在调用时用共用实例的 `i18n.t`；测试里切换语言，两种语言各测一遍。
- 句子里夹着组件（等宽字体、链接、键帽）时用 `<Trans>`，不要把一句话拆成几段分别翻译。
- 日期不用 `Intl`：中文、日文 `10月17日`，英文 `Oct 17`（`time.months` 里是月份的写法）。
- 并列的几项用 `common.listSeparator`（中文、日文顿号，英文逗号），几句话之间用 `common.clauseSeparator`。
- 英文按钮和标签用句首大写（Sentence case），例如 “Write the ending”。
- 日文的说明和提示用です・ます体，按钮和标签用名词或动词原形（例如“保存”“閉じる”）；引号用「」。
- `make lint` 里的 `scripts/check-i18n.mjs` 检查手机端、网页端、`packages` 的代码里没有含汉字或假名的字符串和 JSX 文字（注释、资源目录、测试文件除外）。

### 语言设置

- 偏好里加 `language`：`"system"`（跟随系统，默认）、`"zh"`、`"en"`、`"ja"`。
- 跟随系统时：手机端取 `expo-localization` 的 `getLocales()` 第一项，网页端取 `navigator.languages` 第一项；以 `zh` 开头的用中文，以 `ja` 开头的用日文，其他一律用英文。系统语言变了跟着变（网页监听 `languagechange`）。
- 生效：两端的 `state/language.ts` 在 `useLayoutEffect` 里调用 `applyLanguage()`，在绘制之前切换；网页端同时设置 `<html lang>`（`zh-CN` / `en` / `ja`）。
- 手机端启动：`state/language.ts` 一加载就按系统语言初始化；读完存储后如果用户选了别的语言再切换。启动画面本来就等偏好读完才收起，用户看不到切换。网页端的偏好从 localStorage 同步读出，入口在首屏渲染之前就定好语言。
- 设置页“其他”组里加一行“语言”（地球图标 `language`），右侧显示当前选择。点开是选择面板（手机是底部面板，平板和网页是居中对话框），四个选项：跟随系统、中文、English、日本語。每种语言用它自己的文字写，不翻译，看不懂当前界面的人也能找到自己的语言；“跟随系统”下面注明系统现在是哪种语言。选了立刻生效。

### 错误信息

服务端返回的 `title` / `message` 是英文，客户端优先按错误码显示自己的文字（`packages/core/src/api/client.ts`）：

- 接口错误（`describeError`）：先按 `code` 查 `errors.api.<CODE>`；`VALIDATION_ERROR` 带 `field` 时先查 `errors.field.<field>`，不认识的字段在英文界面用服务端更具体的说明。都查不到时：英文界面显示服务端的说明，中文、日文界面按 HTTP 状态码显示一句通用说明（`errors.status.<状态码>`），不夹英文。
- 回合失败（`describeTurnError`，`turn.failed` 事件和回合详情里的 `error`）：先按 `reason` 查 `errors.reason.<类别>`，再按 `code` 查 `errors.turn.<CODE>` 和 `errors.api.<CODE>`；都没有时英文界面用服务端的说明，中文、日文界面说“生成失败”。
- 客户端自己产生的错误（连不上服务器、超时、响应看不懂）直接用 key。
- 意外错误后面附的单号照旧，格式随语言变：`（单号 1a2b3c4d）` / ` (ref 1a2b3c4d)` / `（番号 1a2b3c4d）`。
- 自定义兼容端点的名字由客户端翻译（`models.customProvider`），其他服务商用品牌名。

### 字体

正文的宋体按这一局的语言选，界面文字和角色卡原文用系统字体，各平台按自己的规则回退。

| 文字 | 手机端 | 网页端 |
| --- | --- | --- |
| 故事正文（阅读页、存档卡片上的摘录） | 打包的宋体，按这一局的 `language` 选（`apps/mobile/src/theme/fonts.ts` 的 `serifFor()`）：日文的局用日文子集，其他用中文子集 | 正文所在的元素标上这一局的 `lang`，`tokens.css` 按 `:lang()` 取对应的宋体组 |
| 阅读设置里宋体选项的样字 | 打包的宋体，按界面语言选 | 跟页面的 `lang` |
| 剧本详情页的原始开场白（角色卡原文，语言不定） | 系统字体，缺字由系统回退 | 无衬线组，跟页面的 `lang` |
| 其他界面文字 | 系统字体，iOS / Android 按系统语言挑汉字的写法，不做额外处理 | 无衬线组，跟页面的 `lang` |

- 正文按这一局的语言、不按界面语言：日文界面下也可能读中文存档，日文子集里缺很多简体字。播放状态（`PlayState.language`）在加载存档时从 `playthrough.language` 取。
- 手机端打包两份子集（`apps/mobile/assets/fonts`，生成方法见 `apps/mobile/scripts/font-subset-chars.py`），启动时一起加载：
  - `NotoSerifSC-Regular.ttf`：思源宋体简体中文版，ASCII、GB2312 全部字符和常用标点，约 3.2MB；
  - `NotoSerifJP-Regular.ttf`：思源宋体日文版，ASCII、JIS X 0208 全部字符（假名、符号、第一和第二水准汉字）、2010 年版常用汉字表里 JIS X 0208 没有的 4 个写法（𠮟塡剝頰）、完整的平假名和片假名区段、常用标点，约 3.3MB。
  - 两份不共用字符集：中日共有的汉字在两种字体里写法不同，日本写法的汉字（気、読、図、駅……）也不在 GB2312 里。
  - 不做按需加载：第一次打开日文故事时会先用系统字体画一帧再换字。
- 网页端不打包字体，用系统里装的。`tokens.css` 的字体组分两套：中文和英文用 `PingFang SC`、`Noto Serif SC` 等（拉丁字母取自同一套字体）；日文把 `Hiragino Sans`、`Noto Sans JP`、`Noto Serif JP`、`Hiragino Mincho ProN`、`Yu Mincho` 等排在前面。阅读页上的 `data-narr-font` 标出阅读设置选的是宋体还是黑体，字体组在正文元素上按它的 `lang` 取（在外层取会拿到界面语言的那一组）。
- 手机端界面文字（系统字体）不做按语言的处理：系统是中文、界面选了日文时，界面上的汉字是中文写法，假名正常。日本用户的手机一般是日文系统，不受影响。

## 4 服务端

### 错误信息改英文

- 返回给客户端的错误说明、回合失败说明、模型测试结果的说明全部是英文；命令行工具、日志查看器（vis）、内部异常也改成英文。日志的事件名本来就是英文。
- 回合失败的 JSON（`turn.failed` 事件、`turns.error`）多一个 `reason`：服务商错误的类别（`auth`、`billing`、`rate_limit`、`overloaded`、`context_overflow` 等，取值同 `providers/errors.py` 的 `ErrorClass`），不是服务商错误时为 null。
- 保留的中文都是数据：卡片预览里 `{{user}}` 的替换词（按卡片原文的语言）、世界实体的内部名字、连接测试的中文样本文字（用来检查中文传输不乱码）。

### 提示词的语言

- `playthroughs.language` 早就有（默认 `zh`，之前一直写 `zh`）。`POST /v1/playthroughs` 新增可选字段 `language`（`zh` / `en` / `ja`，不传按 `zh`，别的值返回 422），返回的游玩里也带上它；迁移 0006 给这一列加了 CHECK，0007 把 `ja` 加进去。
- 一局的语言开局时定下，之后不变。
- `runtime/prompts/` 下 `zh/`、`en/`、`ja/` 三个目录，文件一一对应：7 个模板（导演的系统、开场、回合、结局，选项修补，结构化输出重试，世界构建），加上两份数据：
  - `state_block.json`：世界状态块的标签和标点（中文“【场景】”“地点：……”，英文“[Scene]”“Location: ……”）。
  - `schema/seed.json`：世界构建结构化输出的字段说明和工具说明。`domain/world/seed.py` 里的模型不写说明，生成 JSON Schema 时按这一局的语言填进去。
- runtime 的 `PromptBook` 同时加载所有语言，按回合头里的语言取 `PromptLibrary`：开局世界构建、导演（开场、每轮、结局）、选项修补、结构化输出重试，全部用同一种语言。上下文装配器每种语言一个。
- 中文的输出和改动之前逐字节相同（篇幅说明、“未提供”搬进了 `director.system.j2`，状态块的标签搬进了 `state_block.json`），只有世界构建去掉了“所有文字用中文”这一条（版本号升到 2），和“故事语言不做规定”一致。
- 英文模板是中文模板的对应写法，不是逐字直译：数量单位换成英文的说法（“每次 100 到 200 字”换成按词数说，选项“不超过 30 字”换成“不超过 10 个词”），中文特有的写法换成英文习惯。
- 日文模板同样按日文习惯写：篇幅按字数（短 1 回 200〜400 字、适中 400〜800 字、长 800〜1400 字，比中文多一倍左右，因为日文有假名），选项“30 字以内”；第一人称不规定成“私”，让模型按主人公选一个（私・僕・俺）并保持不变；状态块里秘密一节的标题和系统提示词里的说法一致（“監督のみ閲覧可”）。没有名字的主角兜底叫“私”。
- 测试：`tests/unit/runtime/test_prompt_languages.py` 检查每种语言的文件、模板变量、数据文件的键和中文一致，字段说明指向真实的字段，每种语言都能渲染，英文、日文的状态块和上下文是各自的语言；`test_runner.py` 检查英文、日文的一局给导演的是对应语言的提示词；`tests/unit/domain/test_language.py` 检查语言的解析和主角的兜底称呼；`tests/e2e/test_m1_flow.py` 检查开局的 `language`。合规率评测按剧本里写的 `language` 选提示词，`evals/datasets/m0/ryokan_ja.yaml` 是日文剧本（`tests/e2e/test_director_eval_offline.py` 用假模型服务跑通）。

## 6 加一种语言

1. 客户端：在 `packages/core/src/i18n/` 加一个目录（照 `en/` 或 `ja/` 的样子，类型由中文推出；有单复数的语言用 `Messages`，没有的用 `MessagesOtherOnly`），在 `index.ts` 的 `Language`、`LANGUAGES`、`LANGUAGE_NAMES`、`LANGUAGE_TAGS`、`languageOf()` 里登记；`plural.ts` 里补它的复数规则；`api/types.ts`、`api/endpoints.ts` 里游玩的 `language` 加上它。
2. 服务端：在 `runtime/prompts/` 加同名的目录和文件，`domain/story/language.py` 的语言列表和主角的兜底称呼加上它，写迁移放宽 `playthroughs.language` 的 CHECK，同时改 `docs/api/play.md` 和 `docs/data-model/story.md`。
3. 字体：文字和中文差别大的语言（比如日文，汉字写法不同）要单独一份正文字体：手机端用 `apps/mobile/scripts/font-subset-chars.py` 截一份子集放进 `assets/fonts`，在根布局里加载，在 `theme/fonts.ts` 的 `serifFor()` 里登记；网页端在 `tokens.css` 里加一组 `:lang()` 字体。
4. 两边的对齐测试会指出缺了什么；合规率评测可以加一份这种语言的剧本（`evals/datasets/m0/`）。

同一个词在所有页面用同一种译法。
