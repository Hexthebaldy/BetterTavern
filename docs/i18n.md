# 多语言（i18n）技术方案

> 文档索引：[总览](README.md) · [后端](backend.md) · [客户端](client.md) · [测试](testing.md) · [数据模型](data-model/README.md) · [接口](api/README.md)

手机端和网页端的界面支持中文和英文，服务端给 agent 的提示词也有中文、英文两套。本页写清楚哪些东西随语言变、语言存在哪里、怎么传给服务端，以及写代码时要守住的约定。

## 1 范围

两种语言：中文（源语言，所有文字先用中文写）和英文。以后加一种语言，就是加一份客户端资源和一套服务端提示词，不改代码结构（第 6 节）。

随语言变的：

- 手机端、网页端所有界面文字：标题、按钮、提示、空状态、对话框、读屏标签（`accessibilityLabel`、`aria-label`）、输入框占位文字、标签页标题。
- 客户端显示给用户的错误：服务端只给错误码和英文说明，客户端按错误码翻译（第 3 节“错误信息”）。
- 开始新故事表单里的名字建议、内置文风和“不想看到的内容”：英文界面给英文的选项，选中的文字原样发给服务端。
- 服务端给 agent 的提示词，以及拼进模型上下文的固定文字（篇幅说明、世界状态块的标签、开局设定的字段说明）。

不随语言变的：

- 服务端返回的说明（错误的 `title`、回合失败的 `message`、模型测试结果里的 `detail`）：一律英文，不做多语言。
- 故事正文的语言：不做规定，提示词里不写“用某种语言写”。正文一般跟着提示词、角色卡和玩家输入的语言走。
- 角色卡、世界书等用户导入的内容；模型名、服务商的品牌名、token 数（如 `128K`）、错误单号。
- 诊断日志的导出内容（给开发者看，和服务端日志一样用英文）。
- 阅读字体：正文用的宋体（思源宋体子集）自带拉丁字母，英文正文也用它。

## 2 几个决定

| 问题 | 决定 | 原因 |
| --- | --- | --- |
| 用什么库 | i18next + react-i18next | 复数、插值、缺 key 时退回源语言、切换语言时组件自动刷新都是现成的；两端都是 React，共用一套资源 |
| 资源放哪里 | `packages/core/src/i18n/`，两端共用 | 两端的文字大部分相同；共用资源保证同一个按钮在两端叫法一样 |
| 界面语言存在哪里 | 设备上的界面偏好（`PrefsProvider`，和外观、阅读设置放在一起），不放服务端 | 语言是这台设备的显示偏好，和外观一样；不同设备可以不同。数据库里的 `users.locale` 保留不用 |
| 设置入口 | 设置首页“其他”组里单独一行“语言”，和外观、连接测试同级 | — |
| 提示词的语言怎么定 | 开局时客户端把当前界面语言传给 `POST /v1/playthroughs`（`language` 字段），存在这一局的 `playthroughs.language` 上；这一局以后的 agent 调用都按它选提示词 | 一局的提示词语言固定：前缀缓存、回放测试依赖同一局的提示词稳定；之后切换界面语言不影响已有存档 |
| 服务端错误 | 全部改成英文，不做多语言；回合失败另带 `reason`（服务商错误的类别），供客户端翻译 | 服务端不需要知道界面语言；客户端按错误码显示两种语言的文字 |

## 3 客户端

### 库与资源

- 依赖：`i18next`、`react-i18next`（两端），手机端另加 `expo-localization`（读系统语言，Expo Go 自带）。版本锁定，不跟最新补丁。
- `packages/core/src/i18n/`：
  - `zh/`：源语言，按领域分文件（`common`、`shell`、`auth`、`stories`、`play`、`library`、`settings`），`zh/index.ts` 合在一起，定义所有 key。
  - `en/`：同样的文件，类型由中文推出（`types.ts` 的 `Messages`），少 key 或多 key 时类型检查不通过。
  - `index.ts`：创建两端共用的 i18next 实例并同步初始化（资源打在包里，不按需下载），导出 `i18n`、`applyLanguage()`、`resolveLanguage()`、`currentLanguage()`、`lookup()`（按运行时拼出来的 key 取，查不到返回 null）。
  - `plural.ts`：运行环境没有 `Intl.PluralRules` 时补一个只认中文、英文的最小实现（i18next 没有它会把中文的单数也当成 `one`）。
  - `i18n.test.ts`：两种语言的 key 一一对应、插值变量和组件标签（`<mono>`、`<link>`、`<kbd>`）一致、英文的复数齐全、没有空文字。
- key 分两层：`领域.名字`，例如 `common.retry`、`settings.language`、`play.writingNext`。一级领域大致按页面分：`common`、`time`、`errors`、`nav`、`server`、`auth`、`stories`、`library`、`scenario`、`start`、`cardEdit`、`play`、`reading`、`world`、`settings`、`appearance`、`language`、`account`、`models`、`probe`、`diagnostics`、`shortcuts`、`import`、`notFound`。
- 插值写 `{{name}}`。复数：调用时传 `count`；中文只写 `key_other`，英文写 `key_one` 和 `key_other`。
- 类型：`CustomTypeOptions` 指向中文资源，`t("不存在的key")` 在类型检查时报错。缺 key 时退回中文（`fallbackLng: "zh"`）。

### 写法约定

- 组件里用 `const { t } = useTranslation()`。每个直接渲染文字的组件自己调用，列表里的一行也一样：切换语言时，调用了它的组件会自己重新渲染。`memo` 的组件即使只调用 core 里的函数取文字，也要调一次 `useTranslation()` 订阅语言变化。
- 不在模块顶层算出翻译后的常量（模块加载时语言还没定下来，切换后也不会变）。选项表这类常量里存 id，渲染时再取文字（主题名 `appearance.<id>`、快捷键 `shortcuts.items.<id>`、导航 `nav.<name>`）。
- `packages/core` 里返回文字的函数（相对时间、存档状态、模型状态、开始表单的选项、角色卡检查、错误说明等）在调用时用共用实例的 `i18n.t`；测试里切换语言，两种语言各测一遍。
- 句子里夹着组件（等宽字体、链接、键帽）时用 `<Trans>`，不要把一句话拆成几段分别翻译。
- 日期不用 `Intl`：中文 `10月17日`，英文 `Oct 17`（`time.months` 里是月份的写法）。
- 并列的几项用 `common.listSeparator`（中文顿号、英文逗号），几句话之间用 `common.clauseSeparator`。
- 英文按钮和标签用句首大写（Sentence case），例如 “Write the ending”。
- `make lint` 里的 `scripts/check-i18n.mjs` 检查手机端、网页端、`packages` 的代码里没有含汉字的字符串和 JSX 文字（注释、资源目录、测试文件除外）。

### 语言设置

- 偏好里加 `language`：`"system"`（跟随系统，默认）、`"zh"`、`"en"`。
- 跟随系统时：手机端取 `expo-localization` 的 `getLocales()` 第一项，网页端取 `navigator.languages` 第一项；以 `zh` 开头的用中文，其他一律用英文。系统语言变了跟着变（网页监听 `languagechange`）。
- 生效：两端的 `state/language.ts` 在 `useLayoutEffect` 里调用 `applyLanguage()`，在绘制之前切换；网页端同时设置 `<html lang>`（`zh-CN` / `en`）。
- 手机端启动：`state/language.ts` 一加载就按系统语言初始化；读完存储后如果用户选了别的语言再切换。启动画面本来就等偏好读完才收起，用户看不到切换。网页端的偏好从 localStorage 同步读出，入口在首屏渲染之前就定好语言。
- 设置页“其他”组里加一行“语言”（地球图标 `language`），右侧显示当前选择。点开是选择面板（手机是底部面板，平板和网页是居中对话框），三个选项：跟随系统、中文、English。“中文”“English”用各自的语言写，不翻译，看不懂当前界面的人也能找到自己的语言；“跟随系统”下面注明系统现在是哪种语言。选了立刻生效。

### 错误信息

服务端返回的 `title` / `message` 是英文，客户端优先按错误码显示自己的文字（`packages/core/src/api/client.ts`）：

- 接口错误（`describeError`）：先按 `code` 查 `errors.api.<CODE>`；`VALIDATION_ERROR` 带 `field` 时先查 `errors.field.<field>`，不认识的字段在英文界面用服务端更具体的说明。都查不到时：英文界面显示服务端的说明，中文界面按 HTTP 状态码显示一句通用说明（`errors.status.<状态码>`）。
- 回合失败（`describeTurnError`，`turn.failed` 事件和回合详情里的 `error`）：先按 `reason` 查 `errors.reason.<类别>`，再按 `code` 查 `errors.turn.<CODE>` 和 `errors.api.<CODE>`；都没有时英文界面用服务端的说明，中文界面说“生成失败”。
- 客户端自己产生的错误（连不上服务器、超时、响应看不懂）直接用 key。
- 意外错误后面附的单号照旧，格式随语言变：`（单号 1a2b3c4d）` / ` (ref 1a2b3c4d)`。
- 自定义兼容端点的名字由客户端翻译（`models.customProvider`），其他服务商用品牌名。

## 4 服务端

### 错误信息改英文

- 返回给客户端的错误说明、回合失败说明、模型测试结果的说明全部是英文；命令行工具、日志查看器（vis）、内部异常也改成英文。日志的事件名本来就是英文。
- 回合失败的 JSON（`turn.failed` 事件、`turns.error`）多一个 `reason`：服务商错误的类别（`auth`、`billing`、`rate_limit`、`overloaded`、`context_overflow` 等，取值同 `providers/errors.py` 的 `ErrorClass`），不是服务商错误时为 null。
- 保留的中文都是数据：兜底选项（`domain/story/options.py`，按语言分好）、卡片预览里 `{{user}}` 的替换词（按卡片原文的语言）、世界实体的内部名字、连接测试的中文样本文字（用来检查中文传输不乱码）。

### 提示词的语言

- `playthroughs.language` 早就有（默认 `zh`，之前一直写 `zh`）。`POST /v1/playthroughs` 新增可选字段 `language`（`zh` / `en`，不传按 `zh`，别的值返回 422），返回的游玩里也带上它；迁移 0006 给这一列加了 CHECK。
- 一局的语言开局时定下，之后不变。
- `runtime/prompts/` 下 `zh/`、`en/` 两个目录，文件一一对应：7 个模板（导演的系统、开场、回合、结局，选项修补，结构化输出重试，世界构建），加上两份数据：
  - `state_block.json`：世界状态块的标签和标点（中文“【场景】”“地点：……”，英文“[Scene]”“Location: ……”）。
  - `schema/seed.json`：世界构建结构化输出的字段说明和工具说明。`domain/world/seed.py` 里的模型不写说明，生成 JSON Schema 时按这一局的语言填进去。
- runtime 的 `PromptBook` 同时加载两套，按回合头里的语言取 `PromptLibrary`：开局世界构建、导演（开场、每轮、结局）、选项修补、结构化输出重试，全部用同一种语言。上下文装配器每种语言一个。
- 中文的输出和改动之前逐字节相同（篇幅说明、“未提供”搬进了 `director.system.j2`，状态块的标签搬进了 `state_block.json`），只有世界构建去掉了“所有文字用中文”这一条（版本号升到 2），和“故事语言不做规定”一致。
- 英文模板是中文模板的对应写法，不是逐字直译：数量单位换成英文的说法（“每次 100 到 200 字”换成按词数说，选项“不超过 30 字”换成“不超过 10 个词”），中文特有的写法换成英文习惯。
- 测试：`tests/unit/runtime/test_prompt_languages.py` 检查两套的文件、模板变量、数据文件的键一致，字段说明指向真实的字段，两种语言都能渲染，英文的状态块和上下文是英文的；`test_runner.py` 检查英文的一局给导演的是英文提示词；`tests/e2e/test_m1_flow.py` 检查开局的 `language`。

## 5 测试

- 客户端：`packages/core/src/i18n/i18n.test.ts`（资源对齐、语言解析和切换）、`api/client.test.ts`（错误按错误码翻译，中英文各一遍）、`scenario/startForm.test.ts`（英文的名字建议、分隔符、摘要）。
- 服务端：见第 4 节最后一条。
- 网页端到端：`apps/web/e2e/flow.spec.ts` 按中文跑完整流程（Playwright 配置里 `locale: "zh-CN"`）；`e2e/english.spec.ts` 用英文浏览器跑一条冒烟：界面是英文、登录失败的说明按错误码翻译、设置里切到中文再切回来立刻生效、开局请求带 `language: "en"`。
- `make lint` 里的 `scripts/check-i18n.mjs`（第 3 节）。

## 6 加一种语言

1. 客户端：在 `packages/core/src/i18n/` 加一个目录（照 `en/` 的样子，类型由中文推出），在 `index.ts` 的 `LANGUAGES`、`LANGUAGE_NAMES`、`languageOf()` 里登记；需要的话在 `plural.ts` 里补它的复数规则。
2. 服务端：在 `runtime/prompts/` 加同名的目录和文件，`domain/story/language.py` 的 `PROMPT_LANGUAGES` 加上它，写迁移放宽 `playthroughs.language` 的 CHECK。
3. 两边的对齐测试会指出缺了什么。
